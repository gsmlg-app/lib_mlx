# lib_mlx

iOS-only Flutter FFI management bridge for a local Swift MLX inference core and
OpenAI-compatible localhost server.

The inference path is intentionally HTTP-only:

```text
Flutter app -> http://127.0.0.1:<port> -> Swift server -> MlxCore
```

FFI is used only for lifecycle management:

- load/unload the resident model handle
- start/stop the localhost server
- read runtime status

Tokens, multimodal inputs, tool calls, and reasoning events do not cross FFI.

## Layout

```text
ios/lib_mlx/Sources/MlxCore/   Structured native inference types and stub core
ios/lib_mlx/Sources/MlxServer/ Standalone Swift localhost OpenAI server stub
ios/lib_mlx/Sources/lib_mlx/   @_cdecl lifecycle shim
lib/                           Dart management API and thin OpenAI HTTP client
example/                       iOS runtime harness
src/lib_mlx.h                  ffigen input header for the lifecycle ABI
```

The Swift package under `ios/lib_mlx` is the Flutter plugin SwiftPM package.
The root `Package.swift` mirrors the same native targets for local Swift
validation without Flutter's generated `FlutterFramework` package.

## Dart API

```dart
final runtime = LibMlxRuntime();

final handle = await runtime.loadModel(
  const MlxModelConfig(modelPath: '/local/path/gemma-4-e2b-it-4bit'),
);

final server = await runtime.startServer(
  handle,
  config: const MlxServerConfig(port: 8080),
);

final client = LibMlxOpenAiClient(baseUri: server.uri);
final response = await client.chatCompletions({
  'model': server.modelId,
  'messages': [
    {'role': 'user', 'content': 'Capital of France? One word.'},
  ],
  'temperature': 0,
});
```

## Implemented In This Scaffold

- iOS-only Flutter FFI plugin shape
- SwiftPM package with `MlxCore`, `MlxServer`, and `lib_mlx` targets
- JSON-in/JSON-out lifecycle ABI generated by `ffigen`
- Native localhost server stub for:
  - `GET /v1/models`
  - `POST /v1/chat/completions`
  - `POST /v1/responses`
- SSE streaming stubs for chat completions and Responses, including typed
  Responses lifecycle events, sequence numbers, content part events, reasoning
  text events, and function-call argument done events
- Reasoning kept separate from assistant content in the native structured layer
- Tool calls emitted as structured objects in both endpoint families

## Not Yet Implemented

- MLX Swift model loading
- Gemma 4 prompt rendering and raw native I/O parsing
- Image/audio preprocessing and lazy encoder loading
- Physical iPhone 15 Pro memory and quality gates
- Real tool-loop execution driven by model output

Those are Phase 0A/0C device spikes, not something this host can prove without
the pinned local model and a physical A17 Pro device.

## Regenerate Bindings

```bash
dart run ffigen --config ffigen.yaml
```

## Validate

```bash
flutter analyze
flutter test
swift test
swift build
```

`swift build` uses the root package and validates the native targets on the host.
The iOS plugin package itself is validated by Flutter/Xcode when building the
example app.
